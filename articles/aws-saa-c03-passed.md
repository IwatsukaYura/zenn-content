## はじめに
今回AWS SAA-C03(AWS Certified Solutions Architect - Associate)を受験して無事合格しましたので、勉強期間や教材、勉強方法についてシェアしたいと思います。
またAIも使用しながら学習をしていたのでその点についても触れたいと思います。

![AWSのバッジ](/images/aws-saa/badge.png)

準備期間としては大体3週間で1日平均2時間ほどだったので合計の勉強時間としては約40時間くらいだと思います。
ちなみにスコアは786点でそれなりにギリギリでした。（受験当時は「結構できたし800中盤くらいやろ！」と思っていたので辛い。どこ間違えたのか復習できるようにして欲しい。）

![スコア](/images/aws-saa/score.png)

### 前提
筆者の情報は以下の通りです。
- ソフトウェアエンジニア歴2年
- AWSは仕事でちょこっとだけ触っている
- 個人開発などでメジャーなサービスは利用している

ネットでSAA合格のための合格時間などを検索すると30~90時間とかなり幅があるように、**ご自身のITやAWSの経験によってかなり変動します**。
私の勉強時間の40時間というのも参考程度にしてもらえたらと思います。

## 使用教材
### 0. [AWS SAA試験ガイド](https://docs.aws.amazon.com/ja_jp/aws-certification/latest/solutions-architect-associate-03/solutions-architect-associate-03.html)
こちらはSAAの試験ガイドです。
**試験の内容や概要、出題される可能性のあるサービスまで列挙**されています。
ある程度ざっと眺めた上で、リファレンス的に使用していました。
例えば、以後紹介する問題集の中で出てきたニッチめなサービスや難しい問題に対してそのサービスやこのガイドの中に含まれているかどうかを確認していました。
試験対策の時間も限られているので、ガイドの中に含まれていない場合は優先度を下げていました。

### 1. [ping-t](https://mondai.ping-t.com/g)

https://mondai.ping-t.com/g

AWSやLPICなど複数の資格対策が行えるサイトです。
SAAについては一部無料で問題を公開していますが、無料範囲での問題はかなり限られています。
本格的に対策するとなった場合はサブスクで契約した方がよいでしょう。（2,640円/月）

ping-tは以下の二つの形式で学習を進めることができるため非常におすすめです。
- **各サービスに絞った問題形式**
  - 例：S3の学習がしたかったらS3だけの問題をたくさん解ける
- **模試形式**
  - 本番形式で本番レベルの模試を解くことができる

### 2. [Udemy AWS SAA模擬試験問題集](https://www.udemy.com/course/aws-knan/)

https://www.udemy.com/course/aws-knan/

だいたいのAWS SAAの勉強法ブログで挙げられているUdemy講座ですね。
Udemyの方のレビューではかなり賛否両論あって不安になる方もいると思うので私の意見としては

- 向いてる人
  - AWS SAA資格取得を通じて**AWSの網羅的な知識**を得たい
  - ある程度基本的な問題は解けるがもう少し難しい問題で**更なる知識強化をしたい**
- 向いてない人
  - SAAの資格さえ取れればいい
  - 資格対策に使う時間があまり多くない

という印象を受けました。
レビューの中にもあるように、**正直試験本番より難しい問題はそこそこ含まれている**かなという印象でした。
とはいえ実際本番でどんな問題が出て来るかはわからないですし、どちらにせよSAAの範囲から大きく外れた問題構成ではないため解けるようにしておいて損はないかなと思います。

### 3. [AWS 公式問題](https://skillbuilder.aws/learn/6NV91XYP1P/aws-certified-solutions-architect-associate-official-practice-question-set-saa-c03-ri-ben-yu/DGD9JUJV5F)

https://skillbuilder.aws/learn/6NV91XYP1P/aws-certified-solutions-architect-associate-official-practice-question-set-saa-c03-ri-ben-yu/DGD9JUJV5F

AWS Skill Builderで提供されている無料の公式問題セットです。
これは**20問**しか入っていないですが、公式問題なので一番問題の形式や日本語翻訳の雰囲気がつかめるかと思います。
これは試験日前日に最終確認で実施をして、8,9割近く取れたので安心して試験に挑みました。

## 学習スケジュール
### 1週目: インプット期間
ひたすらping-tのサービス別問題でインプットをしていました。
各サービスの概要や使い方、似ているサービスの違いはどこかに気を使いながらサービスごとの特徴を掴んでいきました。
ping-tは解説も非常に丁寧でわかりやすくまとめてくれています。ただ自分はなかなか読んでいるだけでは頭に入りづらかったりもするので**Notionに簡潔に自分の言葉に直しながらまとめ**ていたりもしました。

![notion](/images/aws-saa/notion.png)


### 2週目：アウトプットメイン→インプット
インプットがある程度終わった段階でping-tの模試形式でアウトプットを開始していきました。

意識していた点は以下の点です。
- 正解・不正解関係なく**全ての問題に対してなぜその選択肢が適切/不適切なのかを理解**する
- **点数が低くても気にしない**
- 自分が**不足している知識がどこなのかを俯瞰**しながら知識の穴を埋めていく

三つ目が割と重要だと考えています。

#### 苦手を分析・分解する
例えば「VPCやサブネット関連の構成」を考える問題が苦手だ！と判明してもいくつかの要素に分解できるでしょう。
- **AWS以前のネットワーク知識不足**（CIDR表記とかルーティングの概念、ステートなど）
- **AWSサービス固有の知識不足**（VPC、AZ、サブネットの違いや、それぞれの役割）
- **組み合わせた時の応用**ができない（プライベートサブネットのEC2からS3への経路、複数のVPC設計）

このように知識には階層があるのでそれぞれに合った知識の補強の仕方や、勉強の仕方があるのでそれを分析していました。

**アウトプット→分析→インプット→アウトプット**
上記のような流れで学習をしてping-tの問題でわからない問題はないくらいのレベルまで上げましょう。

### 3週目：アウトプット期間＆試験慣れ
Udemyの学習に入っていきました。
何周もping-tの問題を解いていると問題と答えを暗記してきちゃうので新しい問題に触れていきました。

Udemyの模擬試験については全6回分収録されているのですが、私は4回分しか解きませんでした。
4回分をしっかり解いて復習すればかなりの知識補強ができます、ただ余裕を持ちたい方は全6回やる価値はあると思います。

ping-tでかなり対策をして解いてもUdemyの模擬試験は **初見では60〜70％** 程度しか取れず結構絶望しました笑
ただ復習をしっかりして、少し時間を空けて二周目で80％くらいの正答率を出せるところまで知識の補強を行いました。

その後 [AWS 公式問題](https://skillbuilder.aws/learn/6NV91XYP1P/aws-certified-solutions-architect-associate-official-practice-question-set-saa-c03-ri-ben-yu/DGD9JUJV5F)を解いて試験を迎えた形になります。

## AIの活用について
Claudeを使用してわからなかった問題の解説や回答の妥当性みたいなものを検証していました。
具体的には**SAA対策専用のSkills**を作成して、私が回答に求める項目や粒度、出力フォーマットを指定して学習を進めていました。

### Claude回答フォーマット

```markdown
## 結論
正解は【選択肢の記号 / サービス名】。理由をひとことで。

## なぜこの答えか
この問題が問うている観点(可用性/耐障害性/コスト最適化/セキュリティ/疎結合 など)と、
正解に直結するキーワードを明示。「問題文のこの語句 → このサービス」という対応で説明する。

## 他の選択肢がなぜ不正解か
- (A) 〜なので不適。〜なら正解になり得る。
※各選択肢1〜2行。「間違いだが、条件がこう変われば正解になる」まで書けると応用が効く。

## 引っかけポイント / 混同しやすいサービス
出題者が仕掛けた罠、紛らわしい類似サービスとの決定的な違いを1〜3点。
(例: SQS=引き取り型/SNS=配信型、ALB=L7/NLB=L4 など)

## 試験での典型パターン
この論点が本番でどんな言い回し・シナリオで問われるか。「〜という語が出たら〜を疑え」の形で。

## 暗記フック
試験直前に見返せる1行。語呂・対比・キーフレーズなど、短く刺さる形で。
```


### 苦手分野をClaude側に溜める
また、ある程度自分で理解できた問題でもClaudeに投げて自分の知識不足ソースをClaudeに貯めていくようにしていました。
こうすることで、ある程度アウトプットが済んだ後「**私の苦手な分野や知識が足りていないサービスを教えて**」と指示し、**全体的な分析**をさせたりもしていました。

**私が実際に利用していたSkillsは以下で公開**しており、誰でも簡単に利用できますのでこれからSAA取得を目指している人はぜひ使ってみてください。

https://github.com/IwatsukaYura/claude-skills


## 試験の所感
ちなみに試験はオンサイトで受験しました。
以前CLFでオンラインで受験したときに、試験官の英語のアクセントがつよつよだったり、色々試験以外で気にかける部分が多くストレスだったので行ける人はテストセンターでの受験をおすすめします。

本番試験の問題については、想定通り（ping-t模擬試験や公式問題レベル）のレベルだったかなと思います。
ただ思ったより問われるサービスの幅が狭かったように感じました。
- S3
- VPC
- Lambda
- RDS, DynamoDB

この辺りがメインで問題数が多かった気がします。
個人的にはAIや機械学習関連のところとかIAM、権限周りがもう少し出るかなと思ったんですが意外でした。
（とはいえ何が出るかわからないので満遍なく勉強するしかないですよ！！注意喚起！！）

試験時間は140分に対して、かなりゆっくり慎重めに解いて100分くらいで解き終わりました。
そこから見直しフラグを立てた15問くらいを見直して30分余しくらいで終了しました。

### 試験結果について
当日の20時ごろにAWSとCredlyからメールが届きました。
一応5営業日以内の結果通知となっているのですが、他の方の記事とかをみても大体当日の20時前後に合格の通知が来ているみたいです。
（その辺でなんかバッチ回ってるんかな）
